# T12 — Terminal Daemon-Restart Boundary Review

Status: blocked. The test is complete, but required terminal recovery is not.

## Environment

- Host: `voltron` (macOS ARM64)
- Implementations: Rust, Go, C++
- Source revision: `9abaff7-dirty`

## Layer Results

| Layer | Result | Evidence |
|---|---|---|
| Initial terminal/screen | Pass | Alternate-screen sequence and `QWE_T12_BEFORE` were visible before daemon death. |
| Task process continuity | Fail | The terminal process no longer existed after daemon `SIGKILL`. |
| Process identity recovery | Fail | No terminal process remained to re-identify. |
| Session metadata recovery | Fail | Restarted daemon returned `not_found` for the existing session ID. |
| PTY recovery | Fail | The session status endpoint had no recovered PTY. |
| Terminal screen recovery | Fail | No screen state was available after restart. |
| Interactive input recovery | Fail | Input was rejected because the session did not exist. |

Re-launching the daemon against the same socket and SQLite database succeeded,
so the result is specifically terminal-state loss, not failure to restart the
control plane.

## Conclusion

POC terminal recovery is not implemented. A production design must move PTY
ownership and screen state outside the daemon lifetime or explicitly accept
terminal loss at daemon restart. Task/process survival is separate and is
covered by P08.
