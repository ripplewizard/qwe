# T08 — Full-Screen Detach/Reattach Review

Status: provisional pass pending independent human confirmation.

## Environment

- Date: 2026-11-03 (Asia/Shanghai)
- Host: `hyperion` (Linux x86_64; distribution metadata only)
- Implementations: Rust, Go, C++
- PTY size: 24x80
- Neovim: 0.10.4
- Fixture: 300 numbered lines
- Source revision: `9abaff7-dirty`

## Scenario

For each implementation, a real QWE session launched Neovim with line numbers.
The client sent `G`, scheduled a Neovim timer that emitted
`QWE_T08_DETACHED_OUTPUT` after 700 ms, detached, waited for the timer output,
reattached by the same lease owner, sent `gg` + `Ctrl-D`, and finally sent an
Ex command that emitted `QWE_T08_REATTACHED_INPUT`.

## Observed

- The PTY and Neovim process remained running while detached.
- Output generated after detach was present in the reattach snapshot.
- Reattach restored the full-screen Neovim view, line-number column, file
  content, status line, and `QWE_T08_DETACHED_OUTPUT`.
- New input after reattach was accepted and `QWE_T08_REATTACHED_INPUT` appeared
  on screen.
- The final observed viewport contained numbered lines 12–33 and status
  `12,1 3%`.
- Rust, Go, and C++ produced the same functional result.

## Limitations

- Restore is achieved by replaying the complete raw PTY byte stream. It is not
  a compact VT-state snapshot.
- Linux pane capture showed literal terminal response artifacts
  (`^[[?1;2;4c^[]11;rgb:...`) because replaying historical output repeats
  device queries. The Neovim screen and retained input stayed usable, but this
  is not suitable as a production attach protocol.
- This is not independent second-person sign-off.
